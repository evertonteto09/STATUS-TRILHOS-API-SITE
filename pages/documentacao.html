Documentação da API

Consulte os endpoints disponíveis da API Status Metropolitano, exemplos de requisições, autenticação, códigos HTTP, limitações e boas práticas de utilização.

URL base

Todos os endpoints da API utilizam a seguinte URL base:

https://status-metropolitano-api.squareweb.app

Autenticação

Atualmente, os endpoints públicos não exigem uma API-Key para serem consultados.

A partir de 12/11/2026, a utilização de API-Key poderá ser exigida em caso de múltiplas requisições ou de acordo com as regras de proteção da API.

Header de autenticação

Quando solicitado, envie sua chave utilizando o header X-API-Key. 

X-API-Key: SUA_API_KEY

Endpoints públicos

Os seguintes endpoints estão disponíveis para consulta:

GET /api/v1/info
GET /api/v1/status
GET /api/v1/historico
GET /api/v1/status/ctpm
GET /api/v1/status/metro
GET /api/v1/status/privadas
GET /api/v1/historico/privadas

Exemplo de requisição

Requisição com API-Key

Exemplo de consulta ao endpoint de status utilizando uma API-Key: 

GET https://status-metropolitano-api.squareweb.app/api/v1/status

Headers:
X-API-Key: SUA_API_KEY

Exemplo utilizando JavaScript

fetch(
    "https://status-metropolitano-api.squareweb.app/api/v1/status",
    {
        method: "GET",
        headers: {
            "X-API-Key": "SUA_API_KEY",
            "Accept": "application/json"
        }
    }
)
.then(response => response.json())
.then(data => {
    console.log(data);
})
.catch(error => {
    console.error("Erro ao consultar a API:", error);
});

Códigos HTTP

A API pode retornar os seguintes códigos HTTP:

Código Descrição
200 Requisição realizada com sucesso.
400 Requisição inválida.
401 Não autorizado. API-Key ausente ou inválida.
503 Serviço temporariamente indisponível.

Limitações

  • O histórico de operação está disponível a partir de 15/09/2026.
  • Consultas referentes a períodos anteriores a 15/09/2026 não estão disponíveis.
  • A disponibilidade dos dados depende das fontes utilizadas pela API.

Boas práticas

Recomenda-se utilizar cache ao consumir a API para evitar requisições repetidas sem necessidade e ajudar a reduzir o fluxo de solicitações.

  • Status: tempo de cache recomendado de 5 minutos.
  • Histórico: tempo de cache recomendado de 1 hora.

Evite realizar várias consultas consecutivas ao mesmo endpoint quando os dados ainda estiverem dentro do período de cache recomendado.
